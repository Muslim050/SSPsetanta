# Отчёт за месяц — что нужно от бэкенда

Основа — `reports-api.md` от 03.10.2026: девять листов, OTT (LIVE) и OTT
(Preroll), поля Live Ads у эфиров. Фронт уже работает по нему:

- вкладки Statistic → **Total** и **Spot** считаются из листов отчёта за
  выбранный месяц;
- **OTT** (Live spot и Preroll) — серверные листы `ottlive` и `ottpreroll`;
- у эфиров и OTT строки сохраняются со всеми полями `pre`, `mid1`, `mid2`,
  `post`, `views` — новые строки с `null`.

Ниже — чего для отчёта ещё не хватает.

| №   | Что                       | Где на фронте                                                                         |
| --- | ------------------------- | ------------------------------------------------------------------------------------- |
| R1  | Листы устройств и городов | Total: «Распределение устройств» и «География аудитории» сейчас на демо-данных        |
| R2  | Секунды у `spot_log`      | Spot: «Standard spot, секунд»; Total: «Хронометраж, сек.» — сейчас из названия ролика |
| R3  | Бренды в строках эфиров   | Live spot SS1/SS2 и OTT: блок «Total ads spots» не сохраняется                        |

---

## R1. Устройства и география аудитории

**Сейчас.** В Total из отчёта считаются эфиры, промо, хронометраж, просмотры
и соцсети. Двух блоков нет ни в одном из девяти листов:

- «Распределение устройств» — Браузер, Smart TV, Телефон, Планшет, доля в %;
- «География аудитории» — город и доля зрителей в %.

Поэтому там демо-значения, которые площадка правит руками. Хранятся они в
браузере и общие для всех договоров и месяцев — к отчёту не привязаны.

**Нужно.** Два листа в шаблоне и в отчёте за месяц — после OTT:

| `code`    | `title`    | `kind`         | Строка              |
| --------- | ---------- | -------------- | ------------------- |
| `devices` | 6. Devices | `device_share` | `{ name, percent }` |
| `cities`  | 6.1 Cities | `city_share`   | `{ name, percent }` |

- `name` — подпись как в файле: «Smart TV», «Телефон», «Ташкент». Не пустая,
  до 100 символов.
- `percent` — доля, число от 0 до 100, до сотых. Правила чтения ячейки — как у
  процента прероллов: формат «%» хранит долю, `0.66` → `66`.
- Порядок строк — порядок в файле, фронт его не меняет.
- Сумму долей на 100 не проверять: в файле она может не сходиться из-за
  округления.
- Итоги не нужны.
- Остальное — как у других листов: приходят в `GET` отчёта, сохраняются
  через `PUT …/sheets/devices` и `…/sheets/cities` с `version`, попадают в
  выгрузку `.xlsx`.
- У отчётов, загруженных раньше, — пустые листы, как сейчас у OTT.

```json
{
  "code": "devices",
  "title": "6. Devices",
  "kind": "device_share",
  "version": 1,
  "rows": [
    { "name": "Smart TV", "percent": 66 },
    { "name": "Телефон", "percent": 30 },
    { "name": "Браузер", "percent": 3 },
    { "name": "Планшет", "percent": 1 }
  ]
}
```

Если этих данных в исходном файле нет и взять их неоткуда — скажите: тогда
фронт уберёт блоки из Total, а не будет держать демо-цифры.

## R2. Секунды стандартных выходов

**Сейчас.** Spot statistic по каждому каналу показывает «Standard spot:
N роликов / N секунд», а Total — «Хронометраж, сек.»: секунды стандартных
выходов плюс секунды Live Ads (`totals.seconds` эфиров).

Ролики — это строки `ss1uzb` и `ss2uzb`. Секунд в листе нет: у `spot_log`
итогов нет, а длительность есть только в названии ролика —
`CLIENT - 10 PER DAY - 30 Sec - UZB TV`. Фронт вытаскивает «30 Sec»
регуляркой; ролики без такой подписи в секунды не входят, о них выводится
отдельное предупреждение. Поменяется формат названия — цифры молча поедут.

**Нужно.** У `spot_log` отдавать `totals: { rows, seconds }` — так же, как у
эфиров. Откуда брать длительность — решать вам: из названия ролика на
сервере или отдельной колонкой шаблона (тогда и `duration` в строке).

## R3. Бренды в строках эфиров — «Total ads spots»

**Сейчас.** У листов `live1`, `live2` и `ottlive` площадка заводит блок
«Total ads spots» — до восьми колонок Brand 1 … Brand 8, в ячейке название
бренда: «Zatecky», «Tuborg Lite», «Carlsberg». Фронт отправляет их в каждой
строке полями `brand1` … `brand8`. В API этих полей нет — при сохранении они,
скорее всего, отбрасываются. Проверьте, что сейчас происходит с
неизвестными полями строки: молча теряются или `400`.

**Нужно.**

- Принимать и хранить `brand1` … `brand8` у `live_event` и `ott_live`:
  строка до 300 символов, поля необязательные.
- Заведённая колонка приходит во всех строках листа (пустая ячейка — `""`),
  незаведённой нет совсем — по этому фронт понимает, сколько колонок
  рисовать. Колонки идут подряд, без пропусков: `brand1`, `brand2`, …
- Отдавать в `GET`, писать в выгрузку и читать при импорте — блок
  «Total ads spots» справа от Views.

```json
{
  "date": "2026-01-01",
  "time": "21:30:00",
  "tournament": "Premier League",
  "event": "Liverpool - Leeds",
  "pre": 30,
  "mid1": 15,
  "mid2": 15,
  "post": 30,
  "views": 233424,
  "brand1": "Zatecky",
  "brand2": "Tuborg Lite",
  "brand3": ""
}
```
